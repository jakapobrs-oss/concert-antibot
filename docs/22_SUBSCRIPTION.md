# 22 — ซับสคริปชั่น: แพ็กเกจสมาชิกเพื่อเข้ารอบสมาชิก

> สถานะ: **โค้ดเสร็จ + ทดสอบบนเครื่องจริงแล้ว** · เขียน 2026-08-20
> ต่อยอดจาก [20_MEMBERSHIP.md](20_MEMBERSHIP.md) (ใครเป็นสมาชิก) และ [21_PRESALE_ROUNDS.md](21_PRESALE_ROUNDS.md) (สมาชิกใช้สิทธิ์รอบไหน)
> ไฟล์นี้ตอบว่า **ผู้ใช้ได้สิทธิ์สมาชิกมาได้ยังไง และสิทธิ์นั้นอยู่นานแค่ไหน**

---

## 1. ขอบเขตรอบนี้ (สำคัญ — อ่านก่อน)

| เรื่อง | รอบนี้ทำ | หมายเหตุ |
|---|---|---|
| แพ็กเกจ (ระดับ × ระยะเวลา) | ✅ | มาตรฐาน/พรีเมียม × 1/3/12 เดือน |
| ประวัติการสมัครแต่ละรอบ (ledger) | ✅ | ตาราง `Subscription` |
| ต่ออายุ/อัประดับ/ยกเลิก | ✅ | |
| เพดานสะสมสิทธิ์ล่วงหน้า | ✅ | 24 เดือน |
| **เก็บเงินจริง** | ❌ **ยังไม่ทำ** | ทีมเคาะ 2026-08-20 ว่ายังไม่คิดเงิน — ทุกแพ็กเกจราคา 0 บาท |
| ตัดเงินอัตโนมัติ (auto-renew) | ❌ | PromptPay เป็นการโอนครั้งเดียว ผูกบัตร/ตัดรอบไม่ได้ ต้องกดต่อเอง |

หน้าจอเขียนกำกับทุกการ์ดว่า **"ฟรี · ช่วงทดลอง — ยังไม่เปิดเก็บค่าสมาชิก"** เพื่อไม่ให้ผู้ใช้เข้าใจว่าจ่ายเงินไปแล้ว

---

## 2. โครงสร้าง: ledger กับ state แยกกันชัด

```
Subscription (ledger)          Membership (state)
─────────────────────          ──────────────────
รอบที่ 1  ก.ย.–ธ.ค. 2570   ──┐
รอบที่ 2  ธ.ค. 70–มี.ค. 71 ──┼──►  tier / expiresAt ปัจจุบัน  ◄── ด่านตรวจทุกจุดอ่านตรงนี้
รอบที่ 3  (ยกเลิกแล้ว)     ──┘
```

- **`Subscription`** = ประวัติว่าสมัครแพ็กเกจอะไร ช่วงไหน ราคาเท่าไร สถานะอะไร
- **`Membership`** = สิทธิ์ ณ ปัจจุบัน (ระดับ + วันหมดอายุ) — `getActiveMembership()` อ่านจากตารางนี้เท่านั้น
- ทุกครั้งที่สมัคร ระบบเขียน **2 ที่ในทรานแซกชันเดียว** → ไม่มีทางที่ ledger กับสิทธิ์จริงจะขัดกัน

> ⚠️ กฎที่ห้ามแหก: **ห้ามให้ด่านตรวจ (คิว/จอง/รอบ) ไปอ่านตาราง `subscriptions` ตรง ๆ**
> ไม่งั้นจะกลายเป็นสองแหล่งความจริงทันที และเคส "แอดมินให้สิทธิ์เอง" (ไม่มี subscription) จะพัง

---

## 3. แพ็กเกจ

| แพ็กเกจ | ระดับ | ระยะเวลา | ราคาป้าย | ได้อะไรเพิ่ม |
|---|---|---|---|---|
| `STANDARD_1M` / `_3M` / `_12M` | มาตรฐาน | 1 / 3 / 12 เดือน | 0 บาท | เข้ารอบสมาชิก (`MEMBER_ONLY`) |
| `PREMIUM_1M` / `_3M` / `_12M` | พรีเมียม | 1 / 3 / 12 เดือน | 0 บาท | เข้ารอบแฟนคลับ (`FANCLUB`) ซึ่งเป็นรอบแรกสุด |

แพ็กเกจนิยามเป็น **ค่าคงที่ในโค้ด** (`SUBSCRIPTION_PLANS` ใน `lib/subscription.ts`) ไม่ทำเป็นตาราง
เพราะผูกกับระดับสมาชิกที่มีอยู่แค่ 2 ระดับ และไม่ได้เปลี่ยนบ่อยจนต้องให้แอดมินแก้เอง —
ถ้าวันหนึ่งต้องให้แอดมินตั้งราคา/แพ็กเกจเองค่อยยกขึ้นเป็นตาราง `SubscriptionPlan`

## 4. กติกาการตัดสิน

| สถานการณ์ | ผลลัพธ์ | เหตุผล |
|---|---|---|
| ยังไม่เป็นสมาชิก | สมัครได้ทุกแพ็กเกจ | |
| ต่ออายุตอนสิทธิ์ยังไม่หมด | รอบใหม่เริ่ม **ตรงวันที่รอบเก่าจบ** | วันที่เหลือไม่หาย ไม่ทับกัน |
| หมดอายุแล้วค่อยกลับมา | รอบใหม่เริ่มจากวันนี้ + รีเซ็ต "วันเริ่มเป็นสมาชิก" | |
| มาตรฐานอยู่ → ซื้อพรีเมียม | **อัประดับทันที** | ผู้ใช้จ่าย(จะจ่าย)เพื่อสิทธิ์ที่สูงกว่า ต้องได้ใช้เลย |
| พรีเมียมอยู่ → กดแพ็กเกจมาตรฐาน | ❌ ปฏิเสธ พร้อมบอกว่ารอจนรอบปัจจุบันหมด | กันผู้ใช้เผลอทิ้งสิทธิ์พรีเมียมที่ยังเหลือ |
| สิทธิ์คงเหลือ + แพ็กเกจใหม่ > 24 เดือน | ❌ ปฏิเสธ | กันกดรัวสะสมสิทธิ์ (ยิ่งช่วงนี้ฟรี ยิ่งต้องมีเพดาน) |
| ถูกแอดมินเพิกถอน | ❌ สมัครเองไม่ได้ | ต้องให้แอดมินคืนสิทธิ์ (กติกาเดิม docs/20) |
| **ยกเลิกการต่ออายุ** | สถานะรอบเป็น `CANCELLED` แต่ **สิทธิ์ยังใช้ได้จนจบรอบ** | กติกาเดียวกับ docs/20 §5 — ไม่ยึดสิ่งที่ผู้ใช้ได้มาแล้วกลางทาง |

**เรื่องวันที่:** บวกเดือนแบบ **หนีบสิ้นเดือน** — 31 ม.ค. + 1 เดือน = 28 ก.พ. (ไม่ใช่ 3 มี.ค. แบบ `setMonth` ตรง ๆ)
ถ้าปล่อยให้ล้น ผู้ใช้จะได้รอบยาวกว่าที่ซื้อ และวันหมดอายุจะเลื่อนสะสมไปเรื่อย ๆ ทุกครั้งที่ต่ออายุ

**เปลี่ยนจากรอบก่อน:** กติกา "ต่ออายุได้เมื่อเหลือไม่เกิน 30 วัน" ถูกแทนด้วย **เพดานสะสม 24 เดือน**
เพราะแพ็กเกจมีหลายระยะเวลา การล็อกหน้าต่าง 30 วันทำให้ซื้อ 12 เดือนล่วงหน้าไม่ได้เลย

## 5. หน้าจอ

### ผู้ใช้ — `/account/membership`
- การ์ดสถานะ: ระดับ + วันหมดอายุ + วันคงเหลือ + **แพ็กเกจปัจจุบัน**
- การ์ดแพ็กเกจ 6 ใบ แยกกลุ่มมาตรฐาน/พรีเมียม — ใบที่กดไม่ได้จะ**บอกเหตุผลตรงการ์ด**
  (เช่น "คุณเป็นสมาชิกพรีเมียมอยู่ — เปลี่ยนเป็นแพ็กเกจมาตรฐานได้เมื่อรอบปัจจุบันหมดอายุ")
- **ประวัติการสมัคร**: ช่วงเวลา · ราคา · สถานะ (ใช้งานอยู่ / จบรอบแล้ว / ยกเลิกแล้ว)
- ปุ่ม **ยกเลิกการต่ออายุ** พร้อมข้อความกำกับว่าสิทธิ์ยังใช้ได้จนจบรอบ

### แอดมิน — `/admin/memberships`
- แต่ละแถวโชว์ **แพ็กเกจปัจจุบัน** ของผู้ใช้ (และวงเล็บว่ายกเลิกการต่ออายุแล้วหรือยัง)
- ปุ่มเดิมยังอยู่: ต่อ 1 ปี · ให้พรีเมียม/ลดเป็นมาตรฐาน · เพิกถอน
  (แอดมินให้สิทธิ์ = ไม่ผ่าน subscription — เป็นทางลัดที่ตั้งใจให้มี เช่นบัญชีทีมงาน/ผู้สนับสนุน)

## 6. 🔌 รอยต่อสำหรับเปิดเก็บเงินจริง (ยังไม่ทำ)

เมื่อต้องการเปิดเก็บเงิน แก้ 3 จุดนี้ ไม่ต้องรื้อโครง:

1. **ราคา** — แก้ `priceTHB` ใน `SUBSCRIPTION_PLANS` (`lib/subscription.ts`) ที่เดียว
   `Subscription.priceAmount` เก็บ snapshot ราคา ณ ตอนสมัครอยู่แล้ว ประวัติเก่าจึงไม่เพี้ยนตามราคาใหม่
2. **ขั้นตอนจ่ายเงิน** — ใน `subscribeToPlan()` เปลี่ยนจาก "สร้างรอบ + ให้สิทธิ์ทันที"
   เป็น "สร้างรอบสถานะรอชำระ → สร้าง PromptPay QR → ผู้ใช้อัปสลิป → ตรวจผ่าน (`lib/easyslip.ts`) → ค่อยให้สิทธิ์"
3. **กันสลิปซ้ำข้ามระบบ** ⚠️ จุดที่พลาดง่ายที่สุด — ตอนนี้ `slipRef` unique อยู่บนตาราง `payments` (ของค่าตั๋ว)
   ถ้าเพิ่มการจ่ายค่าสมาชิกเป็นตารางใหม่ ต้อง **เช็คข้ามทั้งสองตาราง** ไม่งั้นสลิปใบเดียวใช้ได้ทั้งซื้อตั๋วและซื้อสมาชิก

ข้อควรรู้เพิ่ม: EasySlip โควต้าฟรี 500 ครั้ง/เดือน — ถ้าค่าสมาชิกมาใช้โควต้าเดียวกับค่าตั๋ว ต้องคิดเรื่องแบ่งโควต้า
หรือให้ค่าสมาชิกใช้การอนุมัติด้วยแอดมินแทน (มีหน้า `/admin/refunds` เป็นแพทเทิร์นอ้างอิงอยู่แล้ว)

**ทดสอบบนเครื่องจริง (2026-08-20)** — Postgres จริง คลิกผ่านหน้าเว็บ:

| ขั้น | ผล |
|---|---|
| เปิดหน้าสมาชิก (เป็นพรีเมียมเหลือ ~13 เดือน) | การ์ดมาตรฐานทั้ง 3 ใบถูกปิดพร้อมเหตุผล · พรีเมียม 12 เดือนถูกปิดเพราะชนเพดาน 24 เดือน · พรีเมียม 1/3 เดือนกดได้ |

| ตรวจ DB | `Membership.expiresAt` = วันจบของรอบใหม่เป๊ะ (ledger กับ state ตรงกัน) |
| ประวัติการสมัคร | แสดงรอบ + ราคา "ฟรี" + สถานะ "ใช้งานอยู่" |
| กด "ยกเลิกการต่ออายุ" | รอบเป็น `CANCELLED` แต่ `Membership` ยัง ACTIVE/พรีเมียมถึง 19 ธ.ค. 70 |
| หน้าแอดมิน | แถวผู้ใช้โชว์ "แพ็กเกจ: พรีเมียม 3 เดือน (ยกเลิกการต่ออายุแล้ว)" |

## 8. ที่ยังไม่ทำ

- เก็บเงินจริง + ใบเสร็จ/ประวัติการชำระ (ดู §6)
- ตัดเงินอัตโนมัติ / เตือนก่อนหมดอายุทางอีเมล (ไม่มีระบบ cron ส่งอีเมลในโปรเจกต์นี้)
- คืนเงินค่าสมาชิกตามสัดส่วน (pro-rate) ตอนอัประดับกลางรอบ — ต้องคิดตอนเปิดเก็บเงิน
- แอดมินตั้งราคา/สร้างแพ็กเกจเองผ่านหน้าเว็บ (ตอนนี้แก้ในโค้ดจุดเดียว)
